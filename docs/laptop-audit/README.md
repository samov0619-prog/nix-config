# Аудит ноутбука: Acer → Lenovo

## Состояние и границы

Срез от **08.11.2026**, текущая машина — **Acer**. Имена `laptop` и
`samov-laptop` пока относятся к нему, не к Lenovo. Точная модель Acer не установлена.
Это историческое именование исходного среза. В текущих исходниках после передачи
имён Acer — `laptop-old`/`samov-laptop-old`, Lenovo — `laptop`/`samov-laptop`;
не применять Lenovo профиль на Acer. Пользователь уже успешно применил Acer
NixOS/HM под новыми именами и подтвердил работу после обновления transient hostname.
Целевая новая машина — Lenovo ThinkBook 16 G8+ IPD (21VJ0004CD).
CPU **Core Ultra 7 356H** подтверждён пользователем по BIOS; соответствие Panther
Lake и source-поддержка thermald разобраны в [питании и температурах](power.md).

**Статус на 10.11.2026:** текущий ограниченный source-проход и независимая сверка
завершены; [итог, known issues и пробелы покрытия](closing.md). Полный исходный
план и приёмка Lenovo этим не закрыты. Карта и каталог описывают исторический
срез `a2d1767`, не готовность к установке. После ревью Aider и EasyEffects отключены
в декларациях laptop/desktop; [журнал решений](feedback.md) отслеживает изменения.
Исходные числа ниже не пересчитаны, lock не менялся. После time-policy шага пользователь
успешно выполнил NixOS switch на Acer; Moscow/NTP подтверждены отдельно. Активация
standalone HM этим не установлена. Позже пользователь также подтвердил HM switch на
Acer после backup/lifecycle fixes; это не проверка Minecraft runtime или Lenovo.

## Основания среза

Карта импортов сверена по исходникам после `ea56e3c`. Числа пакетов взяты из
предыдущих точечных offline `nix eval` рабочего дерева на базе `f30e45b`
(с документальной правкой AGENTS и существующей пользовательской правкой Hyprland).
Оценки запрещали import-from-derivation, не запускали сборки и не обновляли lock.
Последующий коммит `ea56e3c` изменил только документацию.

| Список                             | Ссылок на outputs | Уникальных output paths |
| ---------------------------------- | ----------------: | ----------------------: |
| NixOS `environment.systemPackages` |               167 |                     113 |
| HM `home.packages`                 |                89 |                      87 |
| Объединение                        |                 — |                     197 |

Три output paths общие для обоих списков. Повтор ссылки не означает повторную
установку. Это **не число приложений, не transitive closure и не расход диска/RAM**.
Список не охватывает отдельными строками все plugins, runtimeInputs, firmware,
модели, шрифты и graphics libraries. Их существенные точки подключения отмечены в каталоге.

| Вычисленный target       | Значение                 |
| ------------------------ | ------------------------ |
| NixOS                    | `26.05.20260707.0ad6f47` |
| Kernel                   | `6.18.38`                |
| System / HM stateVersion | `25.11` / `25.11`        |

Это locked target, а не проверка свежести upstream. `stateVersion` не является
каналом обновления; его нельзя поднимать на Acer просто ради новой версии пакетов.

## Как читать каталог

- **База** — нужна соответствующая системная функция, но не обязательно именно эта реализация.
- **Workflow** — общий личный сценарий, не техническое требование NixOS.
- **Опция** — отдельный сценарий, отключать только после решения пользователя.
- **Железо** — привязка к Acer; для Lenovo нужны собственные данные.
- **Совместимость** — локальный patch, workaround или version gate с условием пересмотра.
- **Тяжёлое?** — кандидат для измерения, не утверждение о доказанном footprint.

Наличие файла ≠ импорт; импорт ≠ включение всех функций; объявленная unit ≠
автозапуск; вычисленный пакет ≠ установленный или работающий процесс.

## Остатки исходного широкого плана

1. Довести provenance каждого package-list entry до конкретного определения,
   включая upstream defaults и generated outputs; сейчас полный именно список
   локальных module imports, а компоненты сгруппированы по назначению.
2. Проверить все механизмы старта: system/user units, sockets, D-Bus, Hyprland
   `exec-once`, shell и ручной запуск. Первый ограниченный проход — в [карте запуска](startup.md);
   это не полный runtime-аудит. Не переносить выводы из одного механизма на остальные.
3. Сверить target с активными поколениями и ограниченно описать ручное состояние
   Neovim/Lazy/Mason, профилей, приложений и моделей, не читая секреты.
4. Решения по удалениям, модулям, security baseline и обновлениям уже принимались
   отдельными шагами в журнале; это не закрывает первые три пункта автоматически.

Для текущего closing-шага NixOS/HM activation не нужна. Reviewer и родительский
агент выполняли только source/Git/document сверку, без новых tests/builds,
GC, input updates, переименования хостов и действий с дисками. Прежние проверки
и пользовательские активации сохраняют свои границы в журнале, не отменяются этой записью.

## Согласованное направление миграции

В исходниках Acer получил имена `laptop-old` / `samov-laptop-old`, Lenovo —
`laptop` / `samov-laptop`. Переименованы каталоги, outputs, hostname, helpers,
completions, тесты и актуальные команды документации. Старые laptop-next outputs
удалены, не оставлены aliases. Исторические записи сохраняют прежние имена.
[Целевой конфиг Lenovo](../../hosts/laptop/README.md) включает live hardware scan,
PRIME offload без принудительного Steam и проверенный путь SSD. Явный install
guard остаётся до полного update inputs, GPU power/resume и final install review.
Acer NixOS/HM применены пользователем; [результаты и границы проверки](host-renaming.md).

Три поколения NixOS/HM и weekly GC на Acer — компромисс из-за недостатка места на
SSD. Для Lenovo согласованы 10 поколений NixOS + 10 HM и weekly GC через общий
service, без дополнительных таймеров. Zram пока выключен; условия включения и
закомментированный вариант находятся в Lenovo host. Фактический запас места и
давление на RAM проверить после установки и обновлений.
