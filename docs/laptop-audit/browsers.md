# Браузеры и перенос профилей

Ограниченная проверка деклараций и pinned packaging; личные профили, историю,
cookies, авторизацию и содержимое хранилищ ключей агент не читал.

## Что задано конфигурацией

- [GUI set](../../home/gui-set/default.nix) сохраняет Firefox вторым браузером,
  без навязанных профилей, расширений и политик. Chrome — основной.
- `browser-previews.packages.x86_64-linux.google-chrome` выбирает **stable**,
  не beta/dev, несмотря на имя input. Locked версия — **154.0.8037.57**;
  это не утверждение о текущей upstream-свежести. Lock не обновлялся.
- [XDG defaults](../../home/linux/gui-set/xdg.nix) назначают
  `google-chrome.desktop` для HTML/XHTML, HTTP/HTTPS и сохранённых дополнительных
  схем. Selected merged HM evaluation Acer/desktop/Lenovo подтвердила HTTP/HTTPS,
  включённый Firefox, пустые `profiles`, `policies` и `nativeMessagingHosts`.
  Это настроенные HM hosts Firefox, не инвентаризация всех расширений и системных
  native-messaging providers.
- В просмотренном Chrome packaging `commandLineArgs` по умолчанию пуст;
  wrapper добавляет условные Wayland flags, но не фиксирует `--password-store`
  или `--user-data-dir`. Пользовательские launchers/flags и живой процесс не
  проверялись. Ошибки, требующей менять настройки браузеров, здесь не установлено.

## Firefox: configPath не равен автоматической миграции

Selected evaluation даёт `.mozilla/firefox` для Acer/desktop с прежним HM
`stateVersion` и `.config/mozilla/firefox` для свежего Lenovo с `26.05`.
Но pinned HM использует `configPath` для генерируемых файлов: `profiles.ini`
создаётся только при непустом `programs.firefox.profiles`. Сейчас список пуст,
а `wrapPackage` не передаёт `configPath` как флаг расположения профиля браузера.

Следовательно, новое значение опции **не доказывает ни фактический runtime-путь,
ни перенос старых данных**. Путь активного профиля пользователь сверяет в
`about:support`; не переносить каталог в XDG только ради совпадения с HM option.
HM также отдельно предупреждает: смена `configPath` не переносит native messaging
hosts. Не менять `stateVersion` Acer ради этой миграции.

## Chrome: профиль и системное хранилище

[Chromium Linux Password Storage](https://chromium.googlesource.com/chromium/src/+/HEAD/docs/linux/password_storage.md)
описывает автоматический выбор backend и возможность fallback в `basic` при
недоступном хранилище. Это основание **проверить**, а не утверждать, что текущий
Chrome использует определённый backend или что пароли уже защищены/не защищены.
Объявленный `pass-secret-service` сам по себе не доказывает его использование
браузером. Принудительный `--password-store=basic` ради переноса не добавлять.

Одна копия профиля не гарантирует доступ к сохранённым паролям на другом хосте:
может потребоваться прежнее хранилище ключей. Sync также не считать полной
резервной копией профиля, авторизации или всех расширений. Конкретный способ
переноса выбрать отдельно, без запуска sync, экспорта паролей или чтения секретов
в рамках этого аудита.

## Ручная проверка при миграции

Только после ранней приёмки suspend/hibernate Lenovo и перед переносом данных:

1. Самостоятельно сверить активные пути: Firefox `about:support`, Chrome
   `chrome://version` → Profile Path. Не публиковать содержимое этих страниц целиком.
2. Полностью закрыть браузеры и сохранить исходные данные/нужное хранилище ключей
   в защищённой резервной копии. Не удалять Acer-копию; не объединять вслепую два
   уже созданных профиля. Способ восстановления согласовать отдельно.
3. На Lenovo проверить открытие обычной HTTP/HTTPS-ссылки в Chrome, нужные закладки,
   расширения и доступ к сохранённым паролям; при необходимости повторно войти
   вручную. Firefox должен оставаться доступным как второй браузер. Проверка не
   требует раскрывать агенту пароли, cookies или историю.

Это документация: NixOS/HM activation не требуется. Сборки, запуск браузеров,
проверка реального key backend и перенос данных не выполнялись.
