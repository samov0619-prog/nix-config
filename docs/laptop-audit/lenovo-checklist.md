# Lenovo: текущая приёмка

[История подготовки](lenovo-history.md) · [Ошибки загрузки](../../hosts/laptop/boot-errors.md)

Состояние на **12.11.2026**. Lenovo уже установлен и используется; NixOS и standalone
Home Manager применены пользователем. Этот список не требует повторной установки,
переразметки диска или повторения уже принятых сценариев ради галочки.
«Принято пользователем» не означает независимое наблюдение UI агентом; source tests
и read-only snapshots имеют более узкое покрытие, указанное в связанных аудитах.

## Принято в согласованном объёме

- [x] Установка, загрузка с SSD, отдельное применение HM и удаление установочных хвостов.
      Kernel 7.3.4 / NVIDIA 615.78.08 применены; оставшиеся сообщения не скрываются.
- [x] Яркость через `intel_backlight`, панель 3200×2000/165 Гц при scale 1.6,
      гашение/включение встроенного экрана крышкой без сна.
      Загрузка binds и режим экрана подтверждены read-only; минимальная яркость,
      внешний экран и вход с уже закрытой крышкой этим не проверены.
- [x] [Hotkeys](../../home/linux/laptop/README.md): F8 touchpad, F9 ⭐ todo,
      Fn+F1 help, Fn+F11 theme, F10 screenshot. Текущая диктовка и переключение тем
      устраивают пользователя; улучшение распознавания не блокирует переезд.
- [x] Камера, screen sharing и видеозвонки — по подтверждению пользователя.
- [x] Обычный GLX на Intel, explicit GLX/native Wayland Vulkan offload на NVIDIA.
      Патч модуля и finegrained RTD3 обеспечили наблюдаемый suspended/D3cold.
      Один видимый cube wake/render/exit/idle цикл и один Hibernate/session-VPN/
      cube/idle цикл приняты; snapshots подтверждают возврат в idle, не всю UI-последовательность.
      [Свидетельства и ограничения](graphics.md).
- [x] Amnezia автоматически подключается после boot и быстро восстанавливается
      после Hibernate. Совпадение GUI/helper проверено; DNS/split routing/kill-switch
      и многократные циклы не входят в эту приёмку.
- [x] [Ручной GPU-блок Waybar](../../home/linux/laptop/waybar/README.md): измерения
      только после клика на 60 секунд; по истечении остаётся кнопка GPU.
      Пользователь подтвердил возврат GPU ко сну, не независимый замер каждого цикла.
- [x] [Browse udiskie → Yazi](removable-media.md) на смонтированной флешке.
      Installed `inode/mount-point` default подтверждён; unmount/eject и все носители
      этим не проверены.
- [x] [Конфигурация защиты батареи](battery.md) применена: Waybar 15%/2%, active
      UPower, `GetCriticalAction=Hibernate`, installed INI 15/5/2.
      **Фактическое действие на низком заряде не проверено**, достаточность 2% не гарантирована.
- [x] Пользователь принял новые тайминги/поведение уведомлений: общий Mako 15 секунд,
      persistent battery/recording и трёхсекундные full/transcribed notices.
      Это не проверка всех battery/error/charging сценариев или других хостов.
      Подробности: `home/linux/modules/notifications/README.md`.
- [x] Мышь ThinkBook успешно сопряжена/подключена по сообщению пользователя после
      ручного включения штатных диалогов Blueman вместо Mako. Та же настройка теперь
      задана в HM для трёх GUI-профилей, её применение отдельно ещё не подтверждено.
      Это не приёмка автоматического reconnect/resume или исправление всех Bluetooth errors.
- [x] Обновлённый update-helper установлен. Inventory checker `unchanged=26`
      означал совпадение fingerprints, не свежую upstream/аппаратную проверку.
      Реальный полный update/build цикл с новым hook агент не запускал.

## Наблюдать при обычном использовании

Эти пункты не требуют немедленного эксперимента или искусственного разряда.

- [ ] Повторные suspend/Hibernate от сети и батареи с обычной нагрузкой:
      сессия, ввод, экран, VPN, звук и возврат NVIDIA в idle. Один принятый цикл
      не гарантирует все последующие; не опрашивать NVIDIA постоянно ради проверки.
- [ ] Уведомления 15%/2% и автоматическая защита батареи, если пороги встретятся
      естественно. Сохранять работу заранее; не подменять live-заряд и не разряжать
      батарею специально. При отказе Hibernate сначала проверить выбранное UPower действие.
- [ ] Яркость после resume, удобный минимум, сохранение режима дисплея после
      следующего входа и отрисовка нужных приложений/XWayland на scale 1.6.
- [ ] Нужные файловые сценарии по мере использования: chooser, FileManager1,
      архивы Yazi, безопасное отключение USB. Принятый Browse не заменяет эти проверки.
- [ ] Обычная автономность/температуры и память без zram; запас SSD после updates.
      Не менять PPD/термальную policy только из-за сообщения в журнале или used swap.
      GC остаётся weekly с десятью NixOS и десятью HM generations, без тестового GC.

## Отложено по выбору пользователя

- История заряда/температур/PPD и поиск потребляющих приложений; новый сборщик не нужен сейчас.
- Fingerprint/PAM, шифрование и улучшения входа; парольный sudo и autologin не меняются.
- BIOS/firmware, наушники и Bluetooth tuning. Слышимый звук после ручного
  переподключения подтверждён, автоматическое переподключение ещё не принято.
- Внешний монитор, длительная GPU-нагрузка и измерение автономности.
- Улучшение локальной диктовки и отдельный Android/MTP workflow.
- Разбор journal errors без установленного функционального влияния, включая
  WirePlumber/ISH/GP1/SPD5118/panel. Они не объявлены исправленными или безвредными;
  применённые fixes и их regression/removal harnesses сохраняются.

## Отдельно перед запуском Minecraft server/backup

Lenovo сохраняет клиентские приложения, но **не активирует instance/server/backup watcher**.
Это отдельная задача, не требование завершить перенос рабочего ноутбука.

1. Выбрать локальные данные, heap и внешний remote; проверить доступ/квоту вне Git.
2. В отдельном тестовом назначении проверить serve → HTTP-ready → update → Java,
   stop/restart, завершённый FTB ZIP и ротацию. Не использовать рабочий мир для теста.
3. Восстановить архив в отдельный каталог и проверить результат; учитывать Drive trash.
   Не допускать watcher к исторической облачной папке до готовности источника.

[Lifecycle и безопасные проверки](../../home/modules/minecraft/server/README.md).
Git/SSH, browser profiles, Neovim/Lazy/Mason и прочие личные данные требуют
собственного подтверждения пользователя; успешный switch сам по себе их не переносит.
