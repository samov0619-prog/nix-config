# Yazi: создание архивов и отмена пароля

## Контракт и исправление

Общий `home/core-set/shell.nix` сохраняет Yazi/compress из unstable:

- `c a a` — обычный архив;
- `c a p` — архив с паролем; Esc или пустой пароль отменяют операцию;
- в режиме с паролем формат без его поддержки выдаёт ошибку, а не создаёт
  незашифрованный архив;
- каждый вызов начинает с чистых флагов и собственных списков аргументов.

Installed compress 0.6 нарушал последние три условия: после отмены/пустого
пароля продолжал архивирование, для TAR игнорировал password mode, а флаги
и таблицы аргументов переиспользовались между вызовами одного экземпляра Lua-модуля.
Последний случай воспроизведён повторным вызовом entry на стенде, не в живом Yazi.

Минимальный [patch](../../home/core-set/yazi-compress-password.patch) подключён
перед прежними тремя API substitutions. Не заменяет плагин, не меняет клавиши,
формат ZIP по умолчанию, существующие extract/reveal rules или политику overwrite.
Модуль общий для пяти HM outputs, включая Mac/server; standalone корпоративный
Mac OpenCode archive к этому не относится.

Пароль по-прежнему передаётся архиватору в argv upstream-плагином. Это **не**
stdin-only контракт passmenu и не обещание скрыть пароль от процессов того же UID.
Выбор криптографического алгоритма ZIP и поддержка всех архиваторов не менялись.

## Проверки и ограничения

[Восемь тестов](../../home/core-set/test_yazi_compress.py) запускают настоящий
Lua-код плагина, подменяя только Yazi APIs/FS/Command. Проверяют отмену имени,
отмену/пустой пароль, отказ TAR в password mode, обычный ZIP, selected/hovered
filename с пробелами/Unicode/кавычкой и отсутствие переноса пароля между вызовами.
Отдельная проверка исполняет полученные от плагина аргументы настоящим 7zz:
микроскопический искусственный ZIP читается с верным паролем, неверный отклоняется.
Только fixture в `/tmp/opencode`, один поток сжатия, без личных файлов и UI.

На старом installed source четыре регрессии воспроизведены; с patch все восемь
тестов прошли. Порядок patch → прежние API substitutions отдельно проверен на
копии installed source с обратимым восстановлением этих трёх substitutions.
Это не Nix build: pristine upstream source отсутствовал локально и не загружался.
Узкая merged HM evaluation Acer подтвердила patch, версии 26.9.1/0.6, клавиши
и archive rules. Полная матрица HM profiles и Darwin runtime не выполнялись.

Для повторения на ещё не обновлённом installed plugin нужны имеющиеся Lua 5.4
и 7zz; пути заменить на свои, ничего автоматически не устанавливается:

```fish
python3 -B home/core-set/test_yazi_compress.py \
    ~/.config/yazi/plugins/compress.yazi/main.lua \
    --patch home/core-set/yazi-compress-password.patch \
    --lua /path/to/lua --seven-zip /path/to/7zz
```

После установки исправленного plugin убрать `--patch ...`: повторное применение
patch к уже исправленному source должно завершаться ошибкой. Без `--seven-zip`
пропускается только реальная ZIP-проверка; без Lua стенд не запускается.
Ruff/Prettier недоступны; изменённый Nix отформатирован nixfmt 1.3.1.

Не проверены настоящие Yazi input dialogs/API integration, UI extraction/preview,
ZIP/RAR через другие backend binaries, все форматы и произвольные недоверенные
имена/архивы. Это узкий regression fix, не полный security audit архиватора.

## Последующая приёмка Acer

После исправления пользователь сообщил: «все ок работает идем дальше».
Это пользовательская приёмка предложенного archive workflow на Acer, не
независимая агентская UI-проверка каждого сценария или подтверждение других hosts.
Точные команды сборки/активации и отдельные результаты всех форматов не сообщались.

## Применение и ручная приёмка

1. Проверить diff. Минимальная сборка только plugin, агентом не запускалась:
   `nix build --no-link .#homeConfigurations.samov-laptop.config.programs.yazi.plugins.compress.package`.
2. На Acer выполнить `home-manager switch --flake .#samov-laptop`;
   NixOS rebuild не нужен. На остальных машинах — их HM profile; Lenovo draft
   на Acer не применять. Корпоративный Mac вручную этим не обновляется.
3. Полностью закрыть и заново открыть Yazi. В отдельной папке с несекретным
   тестовым файлом проверить `c a a`: ZIP создаётся и извлекается в другую папку.
4. `c a p` → имя ZIP → Esc в поле пароля: нового архива нет. Повторить с пустым
   паролем; для `.tar` в этом режиме должна быть ошибка без создания архива.
5. Создать ZIP с отдельным тестовым паролем, проверить распаковку; затем обычный
   ZIP без перезапуска Yazi. Он не должен требовать предыдущий пароль.

При обновлении compress проверить upstream без локального patch теми же тестами;
когда все регрессии устранены upstream, удалить только этот patch и его wiring,
сохранив тесты. Старые API substitutions проверять отдельно, не убирать автоматически.
