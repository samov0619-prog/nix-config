# `/task-analysis` — анализ задачи перед реализацией

Личная команда Samov для дома и корпоративного Mac. Связывает требования с
минимальными изменениями, проверками и ожидаемыми результатами. Выделяет зависимости,
противоречия источников и блокирующие вопросы, не навязывая корпоративный процесс
домашним проектам. Предлагаемый backend-контракт отличает от уже развёрнутого API.

## Использование

```text
/task-analysis <задача>
```

Без аргументов используется задача, уже установленная в разговоре. Если её нельзя
определить однозначно, команда уточняет цель. Результат — соразмерный задаче план
в разговоре: требования → изменения → проверки, с источниками и ограничениями.

Команда разрешает только чтение и анализ: не реализует план, не запускает тесты,
сборки или браузер, не создаёт файлы/комментарии и не делает коммиты. Текущие
агент/модель сохраняются по настройкам команды (`subagent: false`, без overrides).
Skill-дубля и нового агента нет; в Common команда не добавляется.

## Подключение и проверка

Исходник — `commands/task-analysis.md`; регистрация задаётся в
`config/personal-layers.nix` ([описание слоя](PERSONAL-LAYER.md)).
HM декларативно подключает слой; Linux-сборка прошла, activation и установки на Mac нет. Metadata находится в
`commands.task-analysis` личного JSONC,
а `{file:...}` подключает только тело без frontmatter.
Существующий personal config неполным файлом с этой командой не заменяется.

Source-проверки и изолированная регистрация сгенерированных home/corporate-файлов
на 2.4.0 из постороннего CWD без discovery-симлинков прошли. Выполнение, аргументы и сохранение
живой модели/агента пока не проверены; живой сервис и Mac не затронуты.

После подключения:

1. Проверить наличие `/task-analysis`, передачу аргументов и сохранение агента/модели.
2. На безопасной задаче проверить связь требований с изменениями и проверками,
   явные пробелы данных и отсутствие самовольного перехода к реализации.
