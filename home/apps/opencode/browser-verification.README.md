# `/browser-verification` — живая браузерная проверка

Личная команда Samov для дома и корпоративного Mac. Проверяет согласованный
сценарий: условия, действия, ожидание, факт и доказательства. Отмечает версию
приложения, связь с исходниками, использование моков и непроверенное покрытие.

## Использование

```text
/browser-verification <сценарий>
```

Без аргументов используется уже согласованный в разговоре browser-тест. Если
цель или сценарий не установлены, команда уточняет их до взаимодействия с браузером.
Результат — отчёт в разговоре: что прошло, не прошло, заблокировано или не запускалось.

Сейчас используется существующий Chrome MCP. Процедура не зависит от Playwright,
не подключает его и не обещает изоляцию браузера. Чужие вкладки и данные не трогает;
опасные внешние действия требуют отдельного разрешения, если ещё не согласованы.
Сборка, deploy, исправления, файлы отчётов, публикации и коммиты не разрешаются.

Текущие агент/модель сохраняются по настройкам команды (`subagent: false`, без
overrides). Skill-дубля и нового агента нет; в Common команда не добавляется.
`/delegated-review-chrome` остаётся отдельным пассивным аудитом записанных
результатов: он не запускает живую проверку повторно.

## Подключение и проверка

Исходник — `commands/browser-verification.md`; регистрация задаётся в
`config/personal-layers.nix` ([описание слоя](PERSONAL-LAYER.md)).
HM декларативно подключает слой; Linux-сборка прошла, activation и установки на Mac нет. Metadata находится в
`commands.browser-verification` личного JSONC,
а `{file:...}` подключает только тело без frontmatter.
Существующий personal config неполным файлом с этой командой не заменяется.

Source-проверки и изолированная регистрация сгенерированных home/corporate-файлов
на 2.4.0 из постороннего CWD без discovery-симлинков прошли. Выполнение, аргументы, сохранение живой модели/агента и
реальный browser run пока не проверены; живой сервис и Mac не затронуты.

После подключения:

1. Проверить наличие `/browser-verification`, аргументы и сохранение агента/модели.
2. На согласованном безопасном сценарии сверить ожидание с наблюдаемым результатом,
   ограничения покрытия, приватность доказательств и оставленные тестовые данные.
